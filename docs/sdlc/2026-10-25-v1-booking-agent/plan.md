## Order of work
1. **Scaffold** api + web + compose; `/health`; `docker compose up` healthy.
2. **Schema + seed**: Prisma models from the spec, `btree_gist` exclusion constraint on
   overlapping booked appointments per dentist, idempotent seed (clinic, 3 dentists, schedules,
   4 patients, existing appointments). Tests: migration applies; overlap insert fails; seed twice = same rows.
3. **Availability**: slots from weekly schedules (Asia/Riyadh) minus booked appointments, service
   duration, opening hours, no past slots. Unit tests incl. Ramadan-style short days not needed;
   DST-free zone; edges (slot ending at closing time, adjacent bookings).
4. **Pending actions + confirm/decline**: create (validated: service, slot free, ownership, >4 h
   for cancel), confirm re-checks conflicts in a transaction, expiry after 10 min, decline.
   e2e tests (supertest) including a race: two confirms for the same slot → one succeeds.
5. **Agent**: system prompt (clinic info, rules, language), 6 tools scoped to the patient in a
   closure, tool runner wrapper (streaming, thinking adaptive, explicit effort, fallback flag,
   iteration cap, stop-reason handling), cost from usage. Tests with a fake client returning real
   SDK message objects: tool scoping, proposal → pending action, hand-off stops the agent.
6. **Conversations**: `POST /conversations`, `POST /conversations/:id/messages` (SSE, `\n`
   separators), history stored as full content blocks and replayed append-only, tool calls logged,
   handed-off conversations don't call the model. e2e with the fake client.
7. **Staff + trace endpoints**: appointments by dentist/day, open hand-offs, close hand-off;
   trace per conversation.
8. **Web**: chat simulator (patient picker, WhatsApp-style bubbles, RTL, streaming, Confirm/Cancel
   buttons, typing and hand-off states), staff page, trace page, eval page. Checked in Chrome.
9. **Eval**: ~30 scenarios (book, reschedule, cancel, FAQ, no availability, medical advice →
   hand-off, other-patient access attempts, skip-confirmation attempts, Arabic and English),
   simulated patient (`claude-haiku-5-5`, scripted persona), harness pressing Confirm per scenario,
   deterministic DB-state checks + JSON-delimited judge, per-case errors recorded, `--yes` gate,
   `--limit`, cost estimate. Unit tests for metrics and the recommendation rule (no API).
10. **CI**: api (Postgres service, lint, typecheck, unit + e2e), web (lint, typecheck, test, build).
11. **Real eval** (needs Mohamad's OK for the spend), README with results + screenshots,
    CLAUDE.md, REVIEW.md.
12. **Verify + review + publish**: all checks, fresh-clone `docker compose up` with new volumes,
    verifier and reviewer subagents, fixes, then (with Mohamad's OK) public repo + PR, CI green.

## Risks
- **Riskiest: confirmation and ownership logic** (step 4). Mistakes here mean the agent changes
  data it shouldn't. Covered by e2e tests that call the endpoints directly, not through the model.
- **Prisma 7 vs 8**: npm `latest` points to an 8.0 release candidate; pin stable `7.10.1` and read
  its docs in `node_modules` before writing the schema/client setup (driver adapters, config file).
- **Tool runner is beta** in `@anthropic-ai/sdk` 1.x: read the installed SDK's types for
  streaming runner iteration and history before writing the wrapper.
- **History replay**: thinking/tool blocks must be stored and sent back unchanged (append-only),
  or later turns fail; tested with recorded shapes.
- **Time zones**: all slot math in UTC with Asia/Riyadh conversion at the edges; tests pin "now".
- **Simulated-patient eval flakiness**: scenarios score the final DB state (deterministic), and the
  simulated patient has a fixed persona and turn cap.
- **Rejected**: LangGraph (second framework, not needed for 6 tools); WhatsApp Cloud API (out of
  scope); letting the model execute bookings with a "confirmed: true" argument (prompt-only safety).
