## Order of work
1. **Scaffold + CI**: api, web, compose, `/health`, CI workflow (lint, typecheck, test, build) on
   the empty apps. Proof: `docker compose up` healthy; CI green on first push later.
2. **Schema, migrations, seed, readiness**: models from the spec (incl. `version`, frozen payloads,
   client message ids, one-open-hand-off), `btree_gist` exclusion constraint, idempotent seed,
   `/health/ready` (db, migrations, seed). Tests: overlapping insert fails; seed twice = same rows.
3. **Clock + shared validator + availability**: injectable clock; one validator (dentist offers
   service, `[start,end)` fits clinic + dentist schedule, 15-min grid, not past, ≤ 60-day horizon,
   no overlap, ownership/status, ≥ 4 h cutoff); availability from local dates (range ≤ 14 days).
   Tests pin the clock: Riyadh midnight, UTC date crossover, exactly 4 h before, adjacent bookings,
   off-duty dentist, unsupported service.
4. **Pending actions + confirm/decline** (riskiest): bind to conversation + patient, freeze payload
   and appointment version, supersede older pending actions, transactional confirm (atomic claim,
   full re-validation, version check, write, stored outcome), idempotent retries, 404/409/410.
   e2e (supertest, real Postgres): other conversation's action → 404; expired/superseded → 410;
   same-action double confirm → one write; two actions for one slot → one 200 + one 409;
   reschedule/reschedule and reschedule/cancel races; stale version → 409.
5. **Agent**: prompt (clinic info, rules, language, Riyadh "now" after the cache breakpoint), 6
   tools scoped to the conversation's patient, tool runner wrapper (streaming, adaptive thinking,
   explicit effort, fallback flag, iteration cap, stop reasons), cost; measure prompt size vs. the
   minimum cacheable size. Tests with a fake client returning real SDK message objects.
6. **Conversation turns**: create conversation per patient, message endpoint with client message id
   (dedupe), one active turn (409 on concurrent), SSE, store only completed turns (full content
   blocks), disconnect/error → nothing stored + visible resend state, idempotent hand-off and no
   model call while handed off. e2e with the fake client, incl. simultaneous messages and a
   disconnect right after a proposal.
7. **Thin eval slice** (before any UI): event log, confirmation oracle, event-sequence scorer with
   self-tests (correct final state after a violation must fail), 3 scenarios (book, cross-patient,
   medical) runnable with `--limit`; cost estimate and `--yes` gate. Smoke run only with Mohamad's OK.
8. **Staff + trace endpoints**: appointments by dentist/day, open hand-offs, close hand-off; trace.
9. **Web**: chat simulator (patient picker, bubbles, RTL, streaming, Confirm/Cancel with frozen
   details, typing/hand-off/error/resend states), staff page, trace page. Checked in Chrome.
10. **Full eval**: ~30 scenarios (scripted safety + persona flows, AR/EN), judge calibration on ~10
    labeled transcripts, `--repeat N`, per-case errors recorded, report with denominators and
    judge accuracy. Unit tests for metrics and the recommendation rule.
11. **Real eval** (Mohamad's OK for ~$3–6), README with results + screenshots, CLAUDE.md, REVIEW.md.
12. **Verify + review + publish**: all checks, fresh clone with new volumes, verifier + reviewer
    subagents, fixes, then (with Mohamad's OK) public repo + PR, CI green, review comments.

## Risks
- **Riskiest: step 4** (confirmation, ownership, concurrency). Tested at the HTTP layer against real
  Postgres, not through the model.
- **Turn state** (step 6): partial SDK blocks must never be stored; tested with simulated disconnects.
- **Prisma 7 vs 8**: npm `latest` is an 8.0 release candidate; pin `7.10.1` and read its bundled
  docs before writing the client setup.
- **Tool runner is beta** (`@anthropic-ai/sdk` 1.x): read the installed SDK's runner types for
  streaming iteration and message history before step 5.
- **Eval validity**: deterministic oracle + event-log scoring carry the headline; judge-scored
  metrics are reported with the judge's measured accuracy; single runs are labeled as such.
- **Rejected**: LangGraph (not needed for 6 tools); a `/eval` web page (README carries results);
  model-executed bookings with a "confirmed" flag (prompt-only safety); a keyword medical filter
  in v1 (false positives; measured instead).

## Departures from plan
- Step 1: NestJS 12 generates Vitest (not Jest) and oxlint; added `typecheck` (tsc) and
  `format:check` (prettier) scripts. `pnpm test` uses `--passWithNoTests` until unit tests exist.
  pnpm 11 blocks dependency build scripts: approved only `prisma` and `@prisma/engines`.
  Project #1's stack had to be stopped to free ports 3000/8000 (same defaults by design).
- Step 2: `prisma init` (7.10.1) writes `prisma7.config.ts` (kept) and also downloaded Prisma
  "agent skills" into `api/.claude/` and `api/.agents/` plus `skills-lock.json`: removed, as
  unrequested instruction files. The generated client lives in `src/generated/prisma` (git-ignored,
  lint-ignored) so `dist/main.js` keeps its layout; `prisma generate` runs on `postinstall`.
  `prisma` and `dotenv` are runtime dependencies because the container runs
  `prisma migrate deploy` + the seed before starting. Prices are integer halalas; Riyadh is a
  fixed UTC+3 offset (no DST). Exclusion constraint and one-open-hand-off index are hand-written
  SQL in the init migration. e2e tests use a throwaway `clinic_test` database (Vitest global setup).
- Step 3: rules are pure functions in `clinic/booking-rules.ts` (`checkSlot`, `checkChange`,
  `availableSlots`); `ClinicService` only loads data. Availability returns at most 4 slots per day
  (10 total) so a week-long query isn't all one morning. Another patient's appointment is reported
  as `not_found`, exactly like a missing one. `--passWithNoTests` removed now that tests exist.
- Step 4: actions gained a `failed` status (confirmed but no longer valid; stored outcome). Found a
  real race bug while running the e2e suite 60 times (deadlock -> 500, 1 in 55): fixed with a
  P2034 retry via the bugfix procedure (root cause in intent.md). e2e timeout raised to 60 s in the
  Vitest config (the 40-round stress test exceeds Vitest's 5 s default; the locked test is unchanged).
- Step 5: `@anthropic-ai/sdk` 1.3 runs the tool loop over a server-side message thread by default;
  we pass `thread: false` (our database holds the history). History is recorded from the documented
  per-iteration hooks: `stream.finalMessage()` + `runner.generateToolResponse()` (cached tool
  results), never from runner internals. Tools are built per turn with the patient id in a closure.
  The system prompt always carries `cache_control`; whether it actually caches (minimum cacheable
  size) is measured from `usage.cache_read_input_tokens` once a key is available. Pending actions
  and hand-offs created by tools persist even if the turn later fails (they are separate records;
  an undelivered proposal simply expires after 10 minutes).
- Step 6: the SSE stream opens as soon as the turn owns the conversation (an `onStart` hook), not on
  the first text delta, so a failure during a tool call still reaches the client as a "please
  resend" event (found by the failure test: it was a bare 500). Confirm/decline events are replayed
  as `[Clinic system]` user-side text; consecutive user-side messages are merged both when building
  history and when appending the new message (found by the replay test: two user messages in a row).
  A global `ValidationPipe` (whitelist, forbid unknown fields) validates all DTOs.
- Step 7: the eval runs locally (`pnpm eval -- --yes` in `api/`, via `tsx`) against a
  `clinic_eval` database next to `DATABASE_URL`, not in a Docker service: it needs dev
  dependencies (`@nestjs/testing`, `tsx`) the production image prunes. It loads `api/.env` and the
  repo-root `.env`. Scenarios may set `handoff: "any"` when either outcome is acceptable (e.g. a
  cross-patient request). esbuild's install script is declined in `pnpm-workspace.yaml` (tsx uses
  its prebuilt binary); pnpm 11 refuses to run scripts while a build decision is open.
